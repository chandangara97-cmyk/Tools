UFS Scrutiny Tool

Runs entirely in your browser — no Python, no server, no data leaves this device.

What this checks

Point this at the survey folder. Multiple towns are supported, and every file is found no matter how deep it's nested — the picker crawls every subfolder. Put each town in its own subfolder, each containing (at any nesting depth inside it) a Portal Data/ folder with that town's *_listing.xls, *_blockboundary.xls, *_wardboundary.xls, *_ivunitboundary.xls, *_townboundary.xls, and optionally a QGIS/ folder with the block/ward/iv boundary shapefiles, e.g.: 
Survey Folder/
  Solan Town/
    Portal Data/  *_listing.xls  *_blockboundary.xls  ...
    QGIS/         block_boundary.shp/.dbf  ward_boundary.dbf  iv_boundary.dbf
  Baddi Town/
    Portal Data/  ...
    QGIS/         ...
A single-town folder (files directly under Portal Data/ with no town subfolder) still works exactly as before. Every rule below runs independently per town, and results are combined into one report with a Town column so you can tell entries apart.
  1. Listing sequence should start at the North-West corner of the block.
  2. Household count per block should be 120–150; else a remark is required.
  3. Major commercial complexes (banks, dispensaries, etc.) must carry a Landmark Type tag.
  4. Record numbers in Listing/Boundary Excel exports must match the Record No in the GIS attribute table.
  5. Block boundary polygons must not overlap.
  6. New: if a block's "Other Details" description names a house number, owner, or structure (e.g. referring to another entry in that block), that referenced entry must actually exist in the same block's listing — otherwise it's flagged.
  7. New: a block boundary's North/East/South/West description must name a structure that actually exists in that block's listing.
  8. New: Area Type and Auxiliary Information codes must be filled in for each block, and Auxiliary Information should reflect any landmark-type structures (bank, school, hostel, etc.) actually found in that block's listing.
  9. New: structure names mentioned in a block's Other Details (block schedule description) must match a structure actually present in that block's listing — catches typos, word-order swaps, and mismatched blocks.
  10. New (best-effort): structure and owner names embedded directly in the North/East/South/West route text (including "H/o …" owner references) are extracted and checked against the listing. This is free-text parsing, so treat its results as a shortlist to review, not a final verdict.
(Block numbering spiral order still needs manual/GIS visual review, same as before — not auto-checked.)
